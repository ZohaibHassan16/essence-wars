## Commands

### Run Tuning

```bash
# Basic run
cargo run --release --bin tune -- --tag my_experiment

# With options
cargo run --release --bin tune -- \
  --tag baseline \
  --mode vs-greedy \
  --generations 100 \
  --games 200
```

### Analyze Results

```bash
# Latest experiment
uv run python python/scripts/analyze_tuning.py --latest

# Specific experiment
uv run python python/scripts/analyze_tuning.py experiments/mcts/2026-01-12_1430_baseline

# All experiments
uv run python python/scripts/analyze_tuning.py --all

# Force re-generate plots
uv run python python/scripts/analyze_tuning.py --latest --force
```

## Performance: MCTS Simulations

### The Problem: Exponential Time Waste

MCTS simulations scale linearly in compute time, but **opponent quality improves sublinearly** (diminishing returns):

| MCTS Sims | Opponent Strength | Time per Gen | Total Time (100 gens) |
|-----------|-------------------|--------------|----------------------|
| 25        | ~70% optimal      | 3s           | 5 min                |
| **50**    | **~85% optimal**  | **6s**       | **10 min** ⭐        |
| 100       | ~92% optimal      | 15s          | 25 min               |
| 200       | ~95% optimal      | 63s          | 105 min              |
| 500       | ~97% optimal      | 180s         | 300 min              |

**Real user data** (100 generations, 50 games/eval):
- `--mcts-sims 200`: **4087.6s** (68 minutes) 🐌
- `--mcts-sims 50`: **239.7s** (4 minutes) 🚀
- **17x speedup** with minimal quality loss!

### The Solution: Use 50 Simulations

**Why 50 is the sweet spot:**

1. **Faster iteration beats stronger opponent**
   - More generations = better convergence
   - 100 gens @ 50 sims > 10 gens @ 200 sims

2. **Consistent challenge > perfect opponent**
   - Tuner needs stable fitness landscape
   - 50-sim MCTS is already very strong (>> GreedyBot)

3. **Weights converge to high WR anyway**
   - Example: Gen 0 @ 89.6% WR → Gen 40 @ 97.9% WR
   - Already crushing 50-sim opponent; 200 sims just slows training

### Recommended Workflow

```bash
# STEP 1: Fast tuning (50 sims)
cargo run --release --bin tune -- \
  --mode faction-specialist --faction symbiote \
  --tag symbiote_v1 \
  --generations 100 --games 50 --mcts-sims 50

# STEP 2: Thorough validation (200 sims)
cargo run --release --bin arena -- \
  --bot1 mcts --weights1 experiments/mcts/.../weights.toml \
  --bot2 mcts --mcts-sims2 200 \
  --games 500 --progress
```

**Fast iteration + rigorous testing = best results!**

## What Changed?

### ✅ New Workflow
- Rust `tune.rs` creates experiment directory automatically
- All outputs go to `experiments/mcts/{timestamp}_{tag}/`
- Single Python CLI script for complete analysis
- Follows data-strategy.md conventions

### 🔄 File Locations
| Old Location | New Location | Status |
|-------------|--------------|--------|
| `tuning_scaling_data.csv` (root) | `experiments/mcts/{id}/stats.csv` | ✅ Proper |
| `plots/` (anywhere) | `experiments/mcts/{id}/plots/` | ✅ Organized |
| Manual log parsing | Automatic via `analyze_tuning.py` | ✅ Streamlined |
| `scripts/parse_tuning_log.py` | `python/cardgame/analysis/parse_log.py` | ✅ Module |
| `scripts/visualize_tuning.py` | `python/cardgame/analysis/visualize.py` | ✅ Module |

### 📦 What's Included
- **Python infrastructure**: `python/cardgame/infra/experiment.py` (Experiment class)
- **Analysis modules**: `python/cardgame/analysis/` (parse_log, visualize)
- **CLI script**: `python/scripts/analyze_tuning.py` (main entry point)
- **Updated Rust**: `src/bin/tune.rs` (creates experiment dirs)

## Migration Notes

- Old CSV files in root (like `tuning_scaling_data.csv`) are deprecated
- Use new workflow going forward
- Old scripts in `scripts/` still work but deprecated
- All future experiments auto-organized in `experiments/mcts/`
